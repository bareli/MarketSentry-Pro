## Summary

ENH-003 (shipped v0.6.0) nudges a first-time user toward the `custom:marketsentry` dashboard
strategy via a one-time `persistent_notification` with copy-paste YAML. That still requires manually
editing a dashboard, switching to YAML mode, and pasting - the exact friction README's "Auto-
dashboard view" section already describes as advanced HA usage most non-technical users never do.

## Recommended change

Investigate whether HA's dashboard/Lovelace API exposes any way to programmatically add a strategy
view to an existing dashboard (no guaranteed stable public API for this as of this session's HA
knowledge - needs research before promising it), or failing that, a notification action button that
deep-links straight to "add a new view" on the user's default dashboard rather than only describing
the steps in text.

## Relevant files

- `custom_components/marketsentry/config_flow.py` (`_notify_dashboard_strategy`, the ENH-003
  notification this extends)

## Model note

Flagged `model:opus`: needs research into whether HA's frontend/dashboard storage API supports this
at all before any implementation - may turn out infeasible without a frontend-side custom panel,
which would be a much bigger feature than the notification it extends.

## Regression test

None yet - blocked on the feasibility research above.

## Product decision (2026-10-31, D-019)

Deferred, scope narrowed. Researched HA's Lovelace storage/WebSocket surface: no stable public API
exists to create a dashboard view programmatically, only internal/undocumented WS commands and raw
`.storage` file edits, both too risky for an integration that doesn't own the user's dashboard.
Dropped that approach. Kept only the lighter "deep-link to the add-view screen" notification action
as the achievable version, deferred. See `team/decisions.md` D-019.

## Product decision (2026-10-31, D-035)

Implement now. Timing only: D-019's narrowed scope stands (deep-link notification action only).
See `team/decisions.md` D-035.

Extended `_notify_dashboard_strategy` in `custom_components/marketsentry/config_flow.py`: kept the
existing ENH-003/ENH-006 text (YAML strategy snippet, title, `notification_id`) untouched and
appended one new paragraph with a markdown link:

```
[Open your default dashboard in edit mode](/lovelace/0?edit=1) to jump straight to the
**+ Add view** button instead of finding the pencil icon yourself.
```

`/lovelace/0?edit=1` is the default auto-generated dashboard's first view (`url_path` "lovelace",
confirmed by reading the installed `homeassistant.components.lovelace` package: the default
dashboard has no custom `url_path` and resolves to `/lovelace`) with HA frontend's own `?edit=1`
query param, which opens that view already in edit mode - the user's next action is the **+ Add
view** button. This is the closest deep-link achievable per D-019's own finding that there is no
stable API to open the "add view" dialog directly; the `?edit=1` query param is frontend (JS)
behavior, not something the installed Python `homeassistant` package can confirm by static
inspection, so treat it the same as README's other "unverified API facts" pending a live check.
`persistent_notification`'s `ha-markdown` renderer already resolves same-origin relative links
client-side (no new HA dependency beyond the one ENH-003 already added).

**No `strings.json`/`translations/*.json` changes.** This notification's text was already plain,
hard-coded English before this fix - ENH-003's own implementation note records why:
`persistent_notification.async_create` has no `translation_key`/placeholder mechanism, so this
message cannot use the project's 8-locale pattern at all (a confirmed HA API limitation, not an
oversight). There is no existing translated entry for this notification to extend, so none was
added; the new sentence is English-only, consistent with every other line it sits beside.
