## Summary

Every tracked instrument today is price-only - there's no notion of "how much of it" a user holds,
so there's no total portfolio value, only a list of individual prices. A user tracking several
stocks/crypto instruments has to do the quantity x price math themselves outside the integration.

## Recommended change

Add an optional "quantity held" field to the instrument's options step (default empty/untracked, so
this stays opt-in and doesn't change behaviour for anyone using the integration as a pure watchlist
today). When set, expose a derived `position_value` attribute per instrument and a new aggregate
sensor summing all set positions (grouped by provider/kind, matching the card's existing
group-by options). Stays strictly read-only/display - no trading, no brokerage link, consistent
with README's Limitations.

## Product decision (2026-10-31, D-017)

Deferred. Scope resolved: per-kind subtotals only (e.g. a stocks total, a crypto total), no
cross-kind/cross-currency normalization. Cross-kind normalization needs exchange-rate conversion
logic across every pair, adding new accuracy risk the product has never taken on; per-kind
subtotals answer the real need without it. New config field plus new sensor is real feature work,
not this cycle's priority. See `team/decisions.md` D-017.

## Implementation (2026-10-31, D-028)

`OPT_QUANTITY` in `const.py`; optional "quantity held" field in `config_flow.py`'s options step,
string-encoded/blank-means-unset (mirrors the existing `thresholds` field's pattern). `sensor.py`:
`_position_value(ref, quantity, price)` helper (percent-scaled for `outcome` to match
`ProbabilitySensor.native_value`'s 0-100 scale); `position_value` attribute on
`ProbabilitySensor`/`PriceSensor`/`RateSensor`, excluded from the recorder via
`_attr_unrecorded_attributes` (same volatility class as `change_pp`/`change_pct`); a new
`PositionValueTotalSensor` grouped by **`(kind, unit)`**, not kind alone - an fx entry mixing
quote currencies (e.g. EUR/ILS and EUR/USD) gets two separate totals instead of one sensor
silently summing two currencies, which the "no cross-currency normalization" scope decision never
intended. Lives on the provider's connection device, added/removed via the entry's existing
reload-on-subentry-change. `native_value` is `None`, not `0`, until at least one instrument in the
group has both quantity and a live price. Translations: `quantity` field + 4 new entity names,
all 8 locales. Commit `756ee5f`.
