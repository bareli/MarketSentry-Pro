## Summary

Adding an instrument today starts from a blank free-text search box (`async_step_user`'s
`url_or_query` field) - a new user has to already know what to type (a ticker, a Polymarket URL, a
coin id). A short list of well-known examples per provider (e.g. "AAPL, MSFT, TSLA" for Finnhub;
"bitcoin, ethereum" for CoinGecko) would shorten the "what do I even type here" moment.

## Recommended change

Add a few example values to the search step's field description/placeholder per provider (a
copy-only change, all 8 locales), or go further with clickable suggestion chips if the form
selector supports it. Keep it to genuinely well-known instruments, not an exhaustive catalog.

## Relevant files

- `custom_components/marketsentry/config_flow.py` (`STEP_INSTRUMENT_SCHEMA`,
  `async_step_user`)
- `custom_components/marketsentry/translations/*.json` (8 locales, if going the copy-only route)

## Model note

Flagged `model:sonnet`: copy-only change if the simple route is chosen; escalate to `model:opus`
only if the richer "clickable chips" option is picked instead.

## Regression test

None yet - copy-only changes don't typically get their own test case per this project's convention;
add a CFG case only if the richer UI option is chosen.

## Product decision (2026-10-31, D-020)

Implement now, scope resolved: simple route only, example values added to the search field's
description/placeholder, all 8 locales. No clickable chips - that would be a UI feature with no
stated need for it. Copy-only, matches this project's existing precedent (D-007/D-008) for cheap
first-screen onboarding improvements. See `team/decisions.md` D-020.
