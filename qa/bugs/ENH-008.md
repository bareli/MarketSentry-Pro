## Summary

README's "Build status / what to verify before production use" section already lists this as a
known gap: Finnhub's WS/REST field names and free-tier WS symbol limit, Alpaca's exact stream feed
path and trade message shape (the quote shape WAS confirmed live), Frankfurter's base URL
(`.dev` vs `.app`) and parameter names, and Bank of Israel's SDMX series-key format were taken from
documentation/guides, not confirmed by an actual live call this project's sessions. A field-name
mismatch would silently drop data (parsed as missing) rather than raise an error.

## Recommended change

One pass per provider: make a real authenticated call (test/demo keys where required) against each
documented endpoint, diff the actual response shape against what `providers/*.py` currently parses,
and either confirm or fix. Promote each confirmed fact out of the module docstring's "unverified"
list into a normal comment once checked.

## Relevant files

- `custom_components/marketsentry/providers/finnhub.py`, `alpaca.py`, `fx.py` (module docstrings
  already flag the specific unverified facts)
- `README.md`'s "Build status" section (source of the current unverified list, update after)

## Model note

Flagged `model:sonnet`: this is verification legwork against already-documented APIs, not a design
decision.

## Regression test

Add one `tests/providers/test_<provider>.py` case per confirmed fact as it's settled (e.g. a
fixture built from the real response shape, not a guessed one).
