## Summary

README's Limitations section already names this: the card's "change" column is derived from the
sparkline ring buffer (first point vs. last point in the visible window), not the precise windowed
`price_move`/`daily_change` figures the backend detectors actually use to decide whether to fire an
event. The two numbers can disagree (different windows, different precision), so a user reading the
card's percentage and then wondering why no alert fired (or vice versa) is looking at two different
calculations without knowing it.

## Recommended change

Expose the backend's own `daily_change`/`price_move` value as a sensor attribute (if not already
present) and have the card read that directly for its "change" column instead of recomputing an
approximation from the sparkline buffer. Keep the sparkline for its own visual purpose.

## Relevant files

- `card/src/marketsentry-card.js` (the "change" column computation)
- `custom_components/marketsentry/detector.py` (the real `price_move`/`daily_change` values)
- `custom_components/marketsentry/sensor.py` (whichever attribute would carry it to the card)

## Product decision (2026-10-31, D-015)

Implement now. Expose the backend's real `price_move`/`daily_change` value as a sensor attribute;
have the card read it directly instead of recomputing an approximation from the sparkline. Cheap
plumbing fix, no new calculation; fixes a real, README-documented source of user confusion about
why an alert did or didn't fire. See `team/decisions.md` D-015.

## Implementation (2026-10-31)

`detector.py`'s `PriceMoveDetector`/`DailyChangeDetector` now keep `last_delta`/`last_change_pct`
in sync on every `update()` call, not just when firing - no new calculation. `sensor.py` exposes
it verbatim as `change_pp`/`change_pct`; `card/src/rows.js` and `marketsentry-card.js` read it
directly, dropping `changeFromHistory()`'s sparkline approximation for the list row's "change"
column. `marketsentry-instrument-card.js` has the same approximation pattern but was out of this
issue's stated scope - flagged as a possible follow-up, not filed. `qa/PROJECT.md`'s *Deliberate
behaviour* section updated to match. Commit `c6e1c02`.
