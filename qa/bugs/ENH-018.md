## Summary

Current coverage is Polymarket (outcomes), Finnhub/Alpaca (stocks), Frankfurter/Bank-of-Israel (FX),
CoinGecko (crypto). `qa/knowledge/historical-risk-areas.md` already flags "new instrument kind /
new provider" as this codebase's highest-risk change shape, and CoinGecko's rate limit under
sustained load is noted there as genuinely unverified. A new provider (another FX source for
redundancy, a second crypto exchange, or a new `commodity` kind for gold/oil/futures) is worth
planning deliberately against that known risk rather than rushed.

## Recommended change

Pick one next provider (owner's call - not QA's to prioritize) and follow the existing `Provider`
interface (`providers/base.py`) exactly, auditing the four existing providers side-by-side the way
`qa/knowledge/historical-risk-areas.md` recommends, since every real bug this project's QA cycle
found traced back to a new provider/kind not matching an existing sibling's shape (BUG-001,
BUG-005).

## Relevant files

- `custom_components/marketsentry/providers/base.py`, `__init__.py` (the interface and `PROVIDERS`
  registry)
- `qa/knowledge/historical-risk-areas.md` (the standing risk note this item is tracking against)

## Model note

Flagged `model:opus`: new provider = new `InstrumentKind` wiring across the config-flow/const.py
triangle, detectors, translations, and the card - the single riskiest category of change in this
codebase per prior QA findings.

## Regression test

A full `providers/test_<new provider>.py` suite, mirroring the existing four, once a provider is
chosen.

## Product decision (2026-10-31, D-024)

Deferred; which specific provider to add next is the owner's call when this becomes a priority,
not decided now. The record itself names this as the owner's call, not QA's or the PM's to pick;
new-provider work is this codebase's own documented highest-risk change shape. See
`team/decisions.md` D-024.

## Product decision (2026-10-31, D-037)

Implement now. Owner's pick: a second FX source (redundancy alongside Frankfurter/BOI), as a new
`/<source>` suffix within the existing `fx` kind - not a new crypto exchange and not a new
commodity `InstrumentKind`. Scoped this way specifically to avoid the record's own flagged
highest-risk shape (new `InstrumentKind` wiring). Concrete free, no-API-key source left to the
implementer, to be documented here once chosen. See `team/decisions.md` D-037.
