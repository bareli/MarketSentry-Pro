## Summary

Part of the coordinator's "ease first-run setup" brainstorm. `marketsentry-card`'s empty state
(`card/src/marketsentry-card.js`, `groups.length === 0` branch) always shows
`t(lang, "empty_card")` = **"No tracked instruments match this card's filters."** (`i18n.js`). For
a brand-new HACS install with zero instruments added anywhere yet, that reads like the user's
`kinds`/`group_by` config is too narrow, not "you haven't added anything yet, go to Settings." The
view-strategy's own empty state already gets this right for the zero-instrument case
(`strategy-view-logic.js`: `"No MarketSentry Pro instruments are tracked yet. Add one via
Settings > Devices & services > MarketSentry Pro > Add instrument."`) - the plain card just never
got the same treatment.

## Recommended change

In `_render()`, distinguish "zero rows total" (`buildRows(hass).length === 0`) from "zero rows
after `kinds` filtering" (`filtered.length === 0` but `buildRows(hass).length > 0`), and use a new
`empty_card_no_instruments` string (added to all 8 `i18n.js` locales, matching the strategy's
existing wording) for the former. Reuses wording already written and already translated for the
strategy card - no new copy to get translated, just reusing it in one more place.

## Relevant files

- `card/src/marketsentry-card.js` (`_render()`, the `groups.length === 0` branch)
- `card/src/i18n.js` (new `empty_card_no_instruments` key, all 8 languages)
- `card/src/strategy-view-logic.js` (existing wording to reuse, for consistency)
