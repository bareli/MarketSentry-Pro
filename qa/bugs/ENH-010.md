## Summary

Today's sparkline history (`history.py`) is an in-memory ring buffer behind a `marketsentry/history`
WS command - it does not survive a Home Assistant restart, and it isn't queryable through HA's own
History or Statistics UI/cards, which every other long-lived sensor in HA supports natively.

## Recommended change

Register the primary price sensors with `state_class` so HA's `recorder` captures them, and add
long-term statistics (`async_add_external_statistics` or the standard recorder path, whichever fits
a polled, non-cumulative price value) so the sensors show up in HA's own History graphs and the
Statistics card, independent of the card's own sparkline mechanism.

## Relevant files

- `custom_components/marketsentry/sensor.py` (primary Probability/Price/Rate sensors - where
  `state_class` would be declared)
- `custom_components/marketsentry/history.py` (today's in-memory mechanism - stays, serves the
  card's sparkline; this is additive, not a replacement)

## Model note

Flagged `model:opus`: statistics-vs-state_class choice for a price (not cumulative, not a sensor
that resets) needs a careful read of HA's own recorder docs for the right fit - picking the wrong
one silently produces nonsensical long-term stats (e.g. summed instead of last-value).

## Product decision (2026-10-31, D-016)

Deferred. Mechanism resolved: use `state_class` (`SensorStateClass.MEASUREMENT`) on the primary
sensors so HA's recorder auto-generates long-term statistics; not `async_add_external_statistics`
(that API backfills entities that don't report live state, which doesn't apply here). The right
mechanism is simple to state but the correctness risk is silent, and testing needs the CI-only
Linux recorder fixture; worth dedicated implementation time, not a drive-by. See
`team/decisions.md` D-016.

## Implementation (2026-10-31, D-030)

Investigated rather than built: `_attr_state_class = SensorStateClass.MEASUREMENT` was already
correctly set on `ProbabilitySensor`/`PriceSensor`/`RateSensor` as of the very first commit that
wired these entities, confirmed via `git show` against that commit - the D-016 mechanism was
already implemented, just never tested. Added a new regression-test block to `tests/test_sensor.py`
(state_class never TOTAL/TOTAL_INCREASING, native_unit_of_measurement stable/non-empty, native_value
numeric with a live quote and None without one). No application code changed. Commit `942feb0`.

**Still unverified against a real instance** (noted, not acted on): whether HA's recorder actually
produces visible long-term statistics over real elapsed time needs the owner's gated `live`
instance (`qa/CLAUDE.md` §1/§4) - `Evidence unavailable` for that specific check from this
environment.
