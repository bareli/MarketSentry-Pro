## Problem

Most fields in `_options_schema()`'s form carry their unit in the label itself
(`"Daily change trigger (%)"`, `"Large trade threshold (USD)"`, `"Closing soon threshold
(hours)"`, `"Cooldown per event type (minutes)"`). Two don't: **"Hysteresis"** and **"Price move
trigger"** (`move_delta`) have no unit and no `data_description` in
`translations/en.json` (or any of the other 7 locale files - none of them add a `data_description`
block for this schema at all). Reading `detector.py` and `const.py`'s per-kind defaults, both
fields are actually **in the same unit as the instrument's own value**, which differs silently by
kind:

| Kind | `hysteresis` default | `move_delta` default | Unit implied |
|---|---|---|---|
| outcome | 0.5 | 0.5 | percentage points of probability |
| stock | 0.0 | 5.0 | USD |
| fx | 0.0 | 3.0 (crypto) / 2.0 (fx, by const.py) | the pair's quote currency |
| crypto | 0.0 | 2.0 | USD |

None of that is visible on the form itself - a user sees two bare number fields labelled
"Hysteresis" and "Price move trigger" with no indication of what unit to type, or that the right
answer depends on which kind of instrument they're configuring.

## Why it matters

This is the form a non-technical owner fills in right after adding every single instrument (it's
not a buried advanced-settings page - it's step 2 of "add an instrument", see
`qa/plans/CARD-lovelace-card.md`'s/README's own setup walkthrough). "Hysteresis" is also not an
everyday word; without a description, a first-time user has to either guess, leave the default, or
go read `detector.py`'s docstring - which isn't shown anywhere in the HA UI. Getting the unit wrong
(e.g. entering "5" meaning "5%" for an outcome instrument, where 5 actually means "5 percentage
points of hysteresis" - close enough to not notice it's wrong, far enough to change when alerts
fire) silently produces a working-but-not-what-the-user-meant detector configuration, with no
error to catch it.

## Recommendation

Add a `data_description` block to `config_subentries.instrument.step.confirm`/`.reconfigure` in
all 8 translation files (HA renders these as inline help text under each field), e.g.:

```json
"data_description": {
  "hysteresis": "How far the value must move back before the same threshold can fire again, in the same units as this instrument's own value.",
  "move_delta": "Minimum change within the move window that counts as a fast move, in the same units as this instrument's own value."
}
```

Since the exact unit varies by kind, the description can stay kind-agnostic ("same units as this
instrument's value") rather than trying to hardcode USD/pp/currency per case - cheaper to maintain
and still resolves the main ambiguity (is this a raw number, a percent, or something else).

## Kind

`works, could be better` - the fields function correctly and the per-kind defaults are sensible;
what's missing is the in-form explanation a non-technical user needs to change them correctly.

## Prototype

Not offered - this is additive help text under existing form fields (an HA-native
`data_description` block), not a layout or workflow change a mockup would clarify.
