## Summary

This repo has no automated way to execute a blueprint's Jinja templates - every verification so far
(BUG-004, UX-002, UX-003, ENH-006) has been a hand-trace against a real `jinja2.Environment` with
hand-mocked HA template globals (`device_name`, `expand`, `integration_entities`, etc.), which is
slower than a test suite and easy to skip under time pressure. `qa/bugs/ENH-006.md`'s own
verification section names this gap explicitly.

## Recommended change

Build a small, reusable test helper (e.g. `tests/blueprints/conftest.py`) that loads a blueprint
YAML (handling the `!input` tag), substitutes blueprint inputs, and renders its templates through a
`jinja2.Environment` pre-loaded with mock implementations of the HA template globals this project's
blueprints actually use (`device_name`, `expand`, `integration_entities`,
`selectattr`/`is_device_attr` as needed). Add real `pytest` cases for the three blueprints using it,
replacing the ad hoc one-off scripts used for past verifications.

## Implementation (2026-10-31, D-029)

`tests/blueprints/blueprint_harness.py`: loads a blueprint YAML (`!input` PyYAML constructor),
substitutes blueprint inputs (falling back to each input's own declared default - deliberately
*not* auto-binding every input name as a template variable everywhere, the exact distinction
BUG-004 turned on), and builds a `jinja2.Environment` with `expand`/`integration_entities`/
`device_name` mocked against simple `MockState`/`MockDevice`/`MockRegistry` dataclasses. Grepped
all three blueprint YAMLs first - those three globals are the only HA-specific ones any of them
call; everything else is stock Jinja. `device_name`'s contract (`name_by_user or name`, `None` on
no match) is trusted from ENH-006's prior finding, not independently re-derived - the PyPI
`homeassistant` wheel available this session (2025.4.4) predates the `device_name` extension's
current module layout entirely, so it couldn't be re-checked against this repo's targeted version
(2026.2.3). New tests: `test_resolved_announce.py` (BUG-004, 5 cases), `test_daily_digest.py`
(ENH-006 + empty-tracked branch, 4 cases), `test_notify_on_event.py` (1 case). UX-002 (copy-only
wording) intentionally not covered - no template execution involved.
