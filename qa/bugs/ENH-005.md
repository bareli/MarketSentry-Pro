## Summary

Part of the coordinator's "ease first-run setup" brainstorm. Both `async_step_finnhub_credentials`
and `async_step_alpaca_credentials` map `InvalidAuth` to the same shared translation key,
`config.error.invalid_auth` = **"Invalid credentials."** - it doesn't name which provider, and it
doesn't repeat the one piece of guidance that exists (the step's own description text - "Get a
free key at finnhub.io" / Alpaca's feed note), which is still visible on the retry form but easy to
miss once there's also a red error banner drawing the eye. A first-time, non-technical user who
mistypes or truncates a pasted key sees the same terse message a developer would, with no hint
about the most common real cause (partial paste, leading/trailing whitespace from a copy).

## Recommended change

Split the shared `invalid_auth` error key into provider-specific ones in
`config_flow.py` (`errors["base"] = "invalid_auth_finnhub"` / `"invalid_auth_alpaca"`) with
correspondingly specific translation strings, e.g.: "Invalid Finnhub API key. Check you copied the
whole key from finnhub.io with no extra spaces." / "Invalid Alpaca key ID or secret key. Check both
were copied in full from your Alpaca account's API keys page."
