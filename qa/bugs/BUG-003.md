## Summary

`PROV-06` requires every provider's `fetch_snapshot()` to degrade per-ref: one bad instrument must
not drop the whole snapshot. `FxProvider`, `CryptoProvider` and `PolymarketProvider` all implement
this (each ref's failure is caught and skipped, others still return). `FinnhubProvider` and
`AlpacaProvider` do not: their `fetch_snapshot()` loops call `self._get(...)` per ref with **no**
try/except, so if any single ref's REST call raises (`CannotConnect`/`InvalidAuth` - a transient
network blip, a rate limit, or a bad symbol), the exception propagates out of `fetch_snapshot()`
entirely. The `ProviderSnapshotCoordinator` catches that at the top level and raises
`UpdateFailed`, which marks the **entire** coordinator update failed - every tracked instrument
under that provider's config entry (not just the one that failed) goes stale/unavailable until the
next poll succeeds for all of them.

## Steps to reproduce

1. `cd` to the repo, `python -m pytest tests/providers/test_finnhub.py tests/providers/test_alpaca.py -k one_bad_ref -p no:homeassistant -v`
2. Both new regression tests fail: a two-ref snapshot where the second ref's REST call returns
   HTTP 500 raises `CannotConnect` out of `fetch_snapshot()`, so the first (healthy) ref's quote is
   never returned at all.

## Expected

Per PROV-06 (and the pattern already implemented in `fx.py`/`crypto.py`/`polymarket.py`): a single
ref's failure is caught inside the loop and skipped; `fetch_snapshot()` still returns a dict with
quotes for every ref that succeeded.

## Actual

`finnhub.py`'s and `alpaca.py`'s `fetch_snapshot()` have no per-ref try/except around
`self._get(...)`; the first ref to fail aborts the whole call, and the coordinator (`coordinator.py`
`_async_update_data`) converts that into `UpdateFailed` for the entire entry, not just the failing
instrument.

## Evidence

```
FAILED tests/providers/test_finnhub.py::test_fetch_snapshot_one_bad_ref_should_not_drop_the_others
FAILED tests/providers/test_alpaca.py::test_fetch_snapshot_one_bad_ref_should_not_drop_the_others
custom_components.marketsentry.providers.base.CannotConnect: Alpaca request to /stocks/BAD/quotes/latest failed: 500, ...
2 failed, 14 deselected in 5.91s
```
Both new tests reproduce the defect by making one of two refs' REST call return HTTP 500; the
healthy ref's quote is asserted present and is not, because the exception aborts the whole call
before it is ever added to the result dict.

## Likely root cause

`finnhub.py` `FinnhubProvider.fetch_snapshot()` (loop at line ~165-178) and `alpaca.py`
`AlpacaProvider.fetch_snapshot()` (loop at line ~157-174) call `await self._get(...)` with no
try/except inside the `for ref in refs:` loop, unlike `fx.py`'s and `crypto.py`'s equivalents which
wrap the per-ref (or per-batch, for crypto) call and continue past a `CannotConnect`.

## Relevant files

- `custom_components/marketsentry/providers/finnhub.py` (`fetch_snapshot`)
- `custom_components/marketsentry/providers/alpaca.py` (`fetch_snapshot`)
- `custom_components/marketsentry/coordinator.py` (`ProviderSnapshotCoordinator._async_update_data` -
  where the uncaught exception becomes an entry-wide `UpdateFailed`)
- Compare: `custom_components/marketsentry/providers/fx.py` (`fetch_snapshot`),
  `custom_components/marketsentry/providers/crypto.py` (`fetch_snapshot`),
  `custom_components/marketsentry/providers/polymarket.py` (`fetch_snapshot`) - the three providers
  that already do this correctly.

## Recommended remediation

Wrap the `self._get(...)` call per ref in `try: ... except (CannotConnect, InvalidAuth): continue`
(logging at debug level, matching `fx.py`'s `_LOGGER.debug("FX snapshot failed for %s: %s", ...)`
pattern) in both `finnhub.py` and `alpaca.py`'s `fetch_snapshot()`.
