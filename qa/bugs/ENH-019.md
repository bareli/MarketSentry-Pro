## Summary

README's Development section already notes this: `card-ci.yml` is a separate workflow from the
main `Lint and test` gate, and only runs Vitest there - Playwright (the 5 behavioral/screenshot
regression tests covering light/dark/RTL) needs a browser download and isn't part of either
blocking workflow today. A card regression could land on master without either CI workflow catching
it if the change only breaks Playwright's checks.

## Recommended change

Add a Playwright job to `card-ci.yml` (or the main workflow) with the browser-download step cached
between runs, and make it a required status check alongside `Lint and test`/`Validate`.

## Implementation (2026-10-31)

Added a required `e2e` job to `card-ci.yml` (no `continue-on-error`), caching the Playwright
browser install, with `--with-deps` on cache-miss and `install-deps` only on cache-hit. Also added
the workflow file itself to its own path filter plus a `workflow_dispatch` trigger (with an
`update_snapshots` mode) - without that, the commit that added the job would never have triggered
it, since the filter only watched `card/**`. Commits `fc3150a`/`abba110`, `7f5ba61`, `8a81805`.
