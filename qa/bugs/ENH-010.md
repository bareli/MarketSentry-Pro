## Summary

Today's sparkline history (`history.py`) is an in-memory ring buffer behind a `marketsentry/history`
WS command - it does not survive a Home Assistant restart, and it isn't queryable through HA's own
History or Statistics UI/cards, which every other long-lived sensor in HA supports natively.

## Recommended change

Register the primary price sensors with `state_class` so HA's `recorder` captures them, and add
long-term statistics (`async_add_external_statistics` or the standard recorder path, whichever fits
a polled, non-cumulative price value) so the sensors show up in HA's own History graphs and the
Statistics card, independent of the card's own sparkline mechanism.

## Relevant files

- `custom_components/marketsentry/sensor.py` (primary Probability/Price/Rate sensors - where
  `state_class` would be declared)
- `custom_components/marketsentry/history.py` (today's in-memory mechanism - stays, serves the
  card's sparkline; this is additive, not a replacement)

## Model note

Flagged `model:opus`: statistics-vs-state_class choice for a price (not cumulative, not a sensor
that resets) needs a careful read of HA's own recorder docs for the right fit - picking the wrong
one silently produces nonsensical long-term stats (e.g. summed instead of last-value).
