## Summary

Part of the coordinator's "ease first-run setup" brainstorm: the full path from HACS install to
"first instrument visible on a dashboard." Today that path is: install, add a provider, add an
instrument, confirm thresholds - and then stop. The card is auto-registered, so manually adding
`type: custom:marketsentry-card` to an existing dashboard works, but the project's best answer to
"show me everything with zero manual card placement" (the view strategy) is documented only in
README's "Auto-dashboard view" section, reached by: edit a dashboard (pencil icon) > Add view >
open the 3-dot menu > switch to **YAML mode** > paste a `strategy:` block. Switching a view to YAML
mode is advanced HA usage that most non-technical users never do, and nothing inside the product
itself (config flow, the card, a notification) ever mentions this feature exists.

## Recommended change

After a config entry's **first-ever** instrument subentry is created
(`InstrumentSubentryFlow.async_step_confirm`'s `create_entry` branch, gated on
`len(entry.subentries) == 0` at the time this one is being added), raise a one-time, informational
repair/issue via `homeassistant.helpers.issue_registry.async_create_issue` (`severity: "info"`,
`is_fixable: False`) pointing at the exact `strategy: type: custom:marketsentry` YAML snippet
already in README, so it surfaces in Settings > Repairs right when it's first useful instead of
requiring the owner to already know to read the README.

## Relevant files

- `custom_components/marketsentry/config_flow.py` (`InstrumentSubentryFlow.async_step_confirm`)
