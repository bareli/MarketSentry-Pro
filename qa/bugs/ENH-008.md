## Summary

README's "Build status / what to verify before production use" section already lists this as a
known gap: Finnhub's WS/REST field names and free-tier WS symbol limit, Alpaca's exact stream feed
path and trade message shape (the quote shape WAS confirmed live), Frankfurter's base URL
(`.dev` vs `.app`) and parameter names, and Bank of Israel's SDMX series-key format were taken from
documentation/guides, not confirmed by an actual live call this project's sessions. A field-name
mismatch would silently drop data (parsed as missing) rather than raise an error.

## Recommended change

One pass per provider: make a real authenticated call (test/demo keys where required) against each
documented endpoint, diff the actual response shape against what `providers/*.py` currently parses,
and either confirm or fix. Promote each confirmed fact out of the module docstring's "unverified"
list into a normal comment once checked.

## Implementation and findings (2026-10-31)

**Frankfurter: confirmed live, no changes needed.** Direct calls to `api.frankfurter.dev/v1`
(`/latest`, date-range, `/currencies`) all matched the documented contract exactly; `.app`
confirmed to 301-redirect to `.dev`.

**Bank of Israel: confirmed live, one simplification.** `RER_<CCY>_ILS?format=csv` against
`edge.boi.org.il` returns real current data with the exact confirmed field names (`OBS_VALUE`,
`TIME_PERIOD`). The `c[DATA_TYPE]=OF00` filter the code sent turned out unnecessary (every row in
the series is already representative-rate data) - removed it from `_boi_fetch_latest`. Standard
SDMX `startPeriod`/`endPeriod` params confirmed live for date-range queries - **implemented
`fetch_history` for BOI**, which previously returned `[]` unconditionally pending exactly this
verification (`providers/fx.py`'s new `_boi_fetch_history`).

**Alpaca: confirmed the WS feed path, found and fixed a real bug in REST history.**
`wss://stream.data.alpaca.markets/v2/iex` and `.../v2/sip` confirmed as the literal feed-path
values (matches `ALPACA_STREAM_URL_TEMPLATE` already). The REST historical-bars endpoint was
**wrong**: code called `/v2/stocks/{symbol}/bars` expecting a flat `{"bars": [...]}` list;
Alpaca's real endpoint (confirmed via docs.alpaca.markets) is the multi-symbol `/v2/stocks/bars`
with a `symbols` query param, nesting bars under `{"bars": {"<symbol>": [...]}}`. The old code
would have thrown `AttributeError` iterating the response dict's keys as bar objects the moment
anyone with real Alpaca credentials requested history for a tracked stock - **genuinely broken in
production**, not a docs-only gap. Fixed `fetch_history` in `providers/alpaca.py`. The
single-symbol `/quotes/latest`/`/trades/latest` paths used elsewhere were corroborated as still
valid by actively-maintained third-party client libraries and left unchanged. Trade message field
names and the free-tier WS symbol limit remain unconfirmed - no example in Alpaca's current docs
to check against.

**Finnhub: could not confirm by a live call.** No API key available to this session; Finnhub's
own published "demo" token (`token=demo`) returns `401 Invalid API key` on both `/quote` and
`/search` today - no longer live. Creating a Finnhub account is out of scope for this agent to do
on the owner's behalf. The documented WS/REST shapes are corroborated against independent,
actively-maintained third-party sources (a real consumer project's trade-message schema, the
`finnhub_api` Elixir client's REST quote model) that match this file's existing assumptions
exactly - a secondary-source match, not Finnhub's own live response. Get a free key and verify
directly before relying on these in production.

Regression tests: `tests/providers/test_alpaca.py::test_fetch_history_parses_bars` rewritten to
the real endpoint/shape, plus a new `test_fetch_history_ignores_other_symbols_in_a_shared_response`;
`tests/providers/test_fx.py::test_fetch_history_boi_parses_csv_with_date_range` (new, replaces the
old `test_fetch_history_boi_not_implemented_returns_empty`) and
`test_fetch_history_boi_raises_cannot_connect_on_request_failure` (new);
`test_resolve_boi_suffix_selects_official_source` updated to assert the filter is no longer sent.
`ruff`/`mypy`/`pytest tests --ignore=tests/config_flow -p no:homeassistant` all clean, 137 passed.
