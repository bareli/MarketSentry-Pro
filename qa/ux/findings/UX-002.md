## Problem

All three blueprint inputs are meant to be independently skippable (flash the light, speak via
TTS, both, or neither). Only one of the three documents that in its own field description:
`tts_entity`'s description reads "Leave empty to skip the spoken announcement." `flash_light`
("Light to flash (optional)") and `tts_target` ("Media player for announcement (optional)") have
no `description` key at all - the only signal that they're skippable is the word "(optional)" in
the field *name*, with no field description explaining what leaving it empty actually does.

## Why it matters

A user filling in a blueprint-generated automation form sees three fields with equal visual
weight. Two of them explain their own skip behavior inline; one doesn't bother, and the other two
rely on a single word in a four-word label. For someone who isn't the developer and hasn't read
`resolved_announce.yaml`'s source, "(optional)" on a target-entity selector could as easily read
as "optional to narrow this to specific entities" as "optional, leave entirely empty to disable
this feature" - the two have very different outcomes (an empty light-flash step silently does
nothing at runtime; that's the intended behavior, but it should read as intended, not like a
field the user forgot to fill in).

## Evidence

Code review only (`blueprints/automation/marketsentry/resolved_announce.yaml`); the blueprint
input form has never been imported into a live HA instance this session (`qa/CLAUDE.md` §1 gates
importing/running a blueprint on the owner's real instance). `Evidence unavailable` as a
screenshot for that reason - the finding is about the wording in the blueprint's own `input`
block, which is reproduced verbatim below and is the evidence:

```yaml
flash_light:
  name: Light to flash (optional)
  default: []
  selector: { target: { entity: { domain: light } } }
tts_target:
  name: Media player for announcement (optional)
  default: []
  selector: { target: { entity: { domain: media_player } } }
tts_entity:
  name: TTS engine (optional)
  description: Leave empty to skip the spoken announcement.
  default: ""
  selector: { entity: { domain: tts } }
```

## Recommendation

Add a one-line `description` to `flash_light` and `tts_target` matching `tts_entity`'s pattern,
e.g.:

- `flash_light`: "Leave empty to skip the light flash."
- `tts_target`: "Leave empty to skip the spoken announcement (also needs a TTS engine below)."

This is a two-line YAML addition, no logic change.

## Kind

`works, could be better` - the fields already function as skippable; only the in-form wording that
tells a non-developer user so is inconsistent between the three.

## Prototype

Not offered - this is a wording-only change to blueprint field descriptions, not an interface
layout a prototype would clarify.
